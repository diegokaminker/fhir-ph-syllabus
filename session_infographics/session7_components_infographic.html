FHIR Architecture Components

Understanding the key components that make up a comprehensive FHIR-based healthcare system. Each component plays a vital role in ensuring interoperability, security, and efficient data exchange.

Clinical Data Stores

Document Store (DS)

Stores clinical documents with metadata management through document registries.

  • • Clinical document storage
  • • Metadata registry
  • • Document search & retrieval

Granular Data Store (GDS)

Patient-centric repository consolidating data from multiple sources in FHIR format.

  • • Patient-centric view
  • • FHIR resource storage
  • • Multi-source integration

Imaging Repository (IR)

Specialized storage for medical images using DICOM standards.

  • • DICOM standard support
  • • Large file management
  • • Image distribution

Authentication (AUTHE)

Verifies user identity using OAuth 2.0 or OpenID Connect.

  • • Identity verification
  • • OAuth 2.0 support
  • • OpenID Connect

Authorization (AUTHO)

Controls access permissions based on user roles and scopes.

  • • Role-based access
  • • FHIR scopes
  • • Permission management

Consent Management (CONS)

Manages patient consent for data access and sharing.

  • • Patient permissions
  • • Consent tracking
  • • Privacy compliance

Audit Log (AL)

Records all data access activities for compliance and security.

  • • Access tracking
  • • Compliance reporting
  • • Security monitoring

API Gateway (AG)

Centralized entry point for managing client-server interactions.

  • • Request routing
  • • Load balancing
  • • Service management
